# 阅读记录 → 桌宠 → 群聊：压力验收

2026-11-25 · 在现有热榜首页和看山小屋上操作，没有另建聊天页。全部使用虚构读者；大量请求只到本机替身，不向知乎或个人模型压测。

## 一篇文章，两个对照问题

Edge 全新会话：匆匆点进《一页笔记》就返回，不算读过；在《两张书签，留下两种读法》停留后，书架新增一篇。打开桌宠、小屋展示选段、点击「把这段放上桌」，三个动作都没有发起模型对话或文章分析。未共享时先问同一个问题，也是在本机回应。

明确放上桌并发言后，用 `deepseek-v4.1-flash` 验收了 **4 次**：

| 读者动作 | 看到的结果 |
| --- | --- |
| 不复述内容，问「用了哪两种颜色？分别拿来做什么？」 | 柴犬从展示的两句中选出依据：“绿的那张夹在我同意的地方，蓝的那张夹在我想再想想的地方。” 气泡显示通过逐字校验的引文，不显示模型自由编写的事实。[实机画面](reading-pressure/03-blind-question.png) |
| 同一篇里追问「作者把蓝书签往前挪了几页？」 | 后文确实写了“两页”，桌上没有。看山答“桌上这段没有写清这一点，我不能替作者补”，并给出回正文选句的入口说明；没有报页数，也没用不相干的真句敷衍。[实机画面](reading-pressure/03b-outside-excerpt.png) |
| 抛出自己的问题：只标赞同的段落，会不会只看到本来就相信的东西？ | 柴犬转为聊读者的想法，没有继续背原文。 |
| 点「听另一位接话」 | 猫头鹰接到真实的第一句和同一选段，区分了读者的担心和已经发生的事。换篇后导读引的是新篇，再从书架返回旧篇才看到旧聊天。 |

另在本机点名猫头鹰找「我同意」那句，证据卡逐字来自当前文章，并能回到对应来源；此步 **0 次模型请求**。当时知乎热榜不可用，使用的是明确标注的本地试读；这不是当日热榜成功或四个角色质量的统计抽样。

## 压力和故障恢复：测的是哪一层

- **聊天接口**：真实聊天路由 + 临时本机 HTTP 服务 + 固定 12 ms 的模拟模型。一次预热不计入下表。覆盖自由发言、不同动物接话、选中原句、材料不足、无共享材料、伪引文、额度不足和超时。

  | 阶段 | 请求数 / 同时请求 | 进入模拟模型的请求 | 模型同时处理峰值 | 接口 P95（本次） |
  | --- | ---: | ---: | ---: | ---: |
  | 常态 | 160 / 4 | 140 | 4 | 32.7 ms |
  | 突发 | 320 / 16 | 77 | 4 | 33.7 ms |
  | 突发后的恢复 | 16 / 4 | 14 | 4 | 31.9 ms |

  同样是 16 个同时请求，修前曾同时挤进 13 个；修后突发中 203 个因拥挤立刻返回，不排队，40 个缺材料就地拒绝。恢复阶段没有拥挤拒绝。模拟限额、超时和错误引文是预期断言，不能把 496 个请求理解为 496 个成功回答。此限制是**每个服务进程**，不是全站限额；P95 也不是真实模型等待时间。

- **读者操作**：桌面 1200 px / 手机宽度 390 px 交替，6 个独立 Edge 浏览器上下文，在正式构建上每次两位同时操作、分三批完成（27.23 秒）。共 150 次模拟聊天请求、84 条被新发言/撤回/收屋作废的慢回复、24 次本机兜底。验证打草稿不取消上一句、真正发送才取代它；说“不想换话题”时保留选段；“原文别发给模型”在本机撤下，不用为撤下再发一次请求；“这篇先不聊了，我想聊聊面试”是换题，不是让整桌闭嘴。换题后的第一包只有新问题。刷新后保留本机聊天，不恢复共享同意。不同访客的标记不串桌。
- **并发限制说明**：之前同时打开 6 个浏览器会话时，工作站报内存不足。已分别跑通逐人和两人并行；上述 6 人不是 6 人同时在线，不能据此给出线上容量。
- **预览自身**：本机默认开发打包器曾在 6.5 秒内触发 28 次主文档导航，开发通道明确报 `HMR hash mismatch`。只把 `dev:pets` 改为用 Webpack；同机复查，首页稳定后 6.5 秒内没有再次导航。生产构建仍走原路径。
- **原功能回归**：41 个自动用例通过。另在关闭在线模型的正式构建上，用浏览器验证只计前台阅读、猫便签的等待与免打扰、中文输入、刷新续聊、清空阅读聊天不清手账、两种手机宽度，以及模拟的七篇热榜回答只送最近五篇做显式导读。

## 重跑

1. `npm run test:companion`、`npm run typecheck`、`npm run build`，然后 `npm run test:companion:api`。生产接口检查只对本机测试替身发请求。
2. `npm run stress:pets`：独立的 496 次本机 HTTP 压测，无需启动应用或配置密钥。
3. 启动本机应用后，`python scripts/stress_reading.py --readers 6 --parallel 1 --burst 12`。需要 Python Playwright 和 Edge，覆盖两种窗口宽度；聊天与知乎均拦截，不扣额度。有足够内存时设 `--parallel 2` 可复现双读者并发。
4. 真实验收仅在 `npm run dev:pets` 开启的本机个人联调环境：`python scripts/verify_reading_discussion.py --live`；增加 `--shots <目录>` 保存截图。只发送这份试读里的虚构对话。离线模式下省略 `--live`，测阅读和本机导读。不要把 `--live` 用于并发压测。

**剩余边界**：逐字校验能挡住伪引文，但对“真句是否答到点”、读者是在问事实还是聊感受，不是一般性的正确性证明。本次猫头鹰接话最后仍提了一个建议，略超出它“先厘清”的职责。下一轮优先换文章盲测（数字、人物、时间和读者感受交错），分别评估选句相关性和接话是否真的多说了一点有用的东西。

后续在另一篇试读里复测了「只想吐槽／核对一句／想做但不敢」，以及第二位不发言时的落点。见[真实对话与本轮压力复测](handoff-intent.md)。
