| 序号 | 候选项目名称 | 英文 / 副标题 | 命名亮点与记忆点 |
| :--- | :--- | :--- | :--- |
| **1（主推）** | **爪爪圆桌派（PawTable）** | *刘看山与小动物的反内耗情报局* | 借势经典访谈“圆桌派”，但主持人和嘉宾全是高颜值毛茸茸小动物（北极狐、猫猫、猫头鹰、小刺猬）。既有圆桌思辨感（契合知乎问答基因），又有极强的萌宠陪伴感。 |
| **2（强痛点）** | **人间清醒圆桌会（SoberPaws）** | *知乎冲浪防焦虑与纠结诊疗室* | 直击痛点——专治刷知乎时的“怕落后焦虑（FOMO）”与“高赞神仙打架导致的决策瘫痪”，评委一眼看懂场景价值。 |

## 二、 先用大白话厘清两个核心基础问题

### 1. 到底什么是「OAuth（知乎登录授权）」？里面是数据吗？
- **一句话大白话**：OAuth 就跟你在平时玩微信小程序或第三方网站时点的**「微信一键登录」**完全是一回事。
- **它不是一个需要我们自己造的复杂系统，而是知乎官方现成提供的一个“授权钥匙”**：
  1. 别的知乎网友点开我们的网站，点一下页面上的**「用知乎账号一键登录」**按钮；
  2. 页面会自动跳到知乎官方的安全登录页，问他：*“是否同意授权【爪爪圆桌派】读取你的知乎公开信息？”*；
  3. 他点“同意”后，知乎官方就会发给我们一把临时钥匙（`access_token`）；
  4. **里面有什么数据？** 拿到这把钥匙后，我们的程序就能合法读取这位网友在知乎上的**真实昵称、真实头像、一句话签名、他关注了哪些答主（`followees`）、他建了哪些收藏夹（`favlists`）、他最近收藏了哪些帖子（`collections`）、以及他发过的回答/想法列表（`contents`）**！
- **为什么要接它？**
  - **第一（冲大奖）**：黑客松官方明确规定，**通过知乎 OAuth 登录你作品的真实人数，是评定「最佳社区人气奖」的核心指标之一**。
  - **第二（做爆款拉新）**：用户一点登录，我们就能读取他真实的知乎收藏和关注，3 秒给他生成一张**《我的知乎冲浪精神状态 & 专属守护小动物》**诊断卡，用户会非常愿意转发分享。
  - **第三（开发极简）**：只需要大约 50 行后端固定模板代码就能接好，而且即使不登录（游客模式），用户也依然可以直接使用我们网站的核心圆桌功能。

### 2. 我们必须做一个网站（Web 应用）吗？
- **是的，做一个「响应式网页（Web App）」是本次比赛性价比最高、最容易拿奖的形式（由 AI 编码工具直接帮我们生成全套网页代码，不需要手写）**。
- **为什么做网站最好？**
  1. **评委 1 秒体验**：初审评委（知乎各业务线负责人）要审很多作品，提交一个公网网址（URL），评委无论用电脑还是手机点开链接就能直接玩，不用安装任何环境。
  2. **手机/电脑全兼容**：在黑客松活动广场（12.05–12.19）拉票时，绝大多数知乎网友是用手机点进来的，做成自适应网页，安卓/苹果手机和电脑浏览器都能直接打开。
  3. **真实数据直连正式服**：我们的网页前端长成温馨可爱的“小动物圆桌小屋”，但底层直接调用知乎开放接口——里面刷到的热榜是**此时此刻真正的知乎热榜**，搜到的回答也是**真正的知乎高赞回答**。

## 四、 核心痛点与破题逻辑（为什么做「小动物圆桌」）

### 1. 避开红海撞车
活动广场上常见的“待办打卡得小猫（番茄钟套壳）”、“静态收藏夹知识树”或“纯闲聊桌宠”已经高度同质化，且容易被知乎业务线评委判定为“脱离知乎核心问答场景的花瓶”。

### 2. 切中社媒与知乎最真实的双重痛点
用户在刷知乎和社交媒体时，最痛苦的往往不是“找不到文章”，而是以下两个紧密相连的心理痛点：
- **痛点 A：刷热榜/刷技术帖时的「焦虑传染与怕落后（FOMO / Brain Rot）」**
  - *现象*：看了一篇技术帖或职场帖觉得焦虑，平台算法为了留存就会疯狂推送同类焦虑帖（“大模型淘汰程序员”、“同龄人年薪百万”、“35 岁危机”）。用户因为害怕落后只能不断刷，越刷越恐慌内耗，最后产生习得性无助甚至逃离社区。
- **痛点 B：遇到现实纠结去搜索时的「高赞神仙打架与劝退迷茫」**
  - *现象*：当用户想做一个具体决定（“去深圳还是留老家？”、“秋招选大厂边缘还是小厂核心？”、“某产品到底是不是智商税？”）去搜知乎时，前排 10 个高赞回答有 5 个吹上天、5 个无脑劝退，外加利益相关软广。一个人看的时候根本分不清谁是幸存者偏差、哪条经验才真正适合自己。

### 3. 核心价值主张：不与平台算法对抗，把「焦虑与纠结」转化为「掌控感与陪伴」
我们不是做一个劝用户“关掉知乎”的拦截器，而是帮用户从每一篇制造焦虑或分歧的帖子里拿走三样东西：
1. **祛魅脱水（剥离情绪水分）**：测出帖子的“含焦量/幸存者偏差指数”，把博眼球的恐慌修辞与真实的客观事实剥离开。
2. **圆桌交锋（看清正反底牌）**：用几只性格鲜明的小动物分别代表不同立场（知乎过来人踩坑经验 vs 全网权威统计数据 vs 软广鉴伪），帮用户把神仙打架的回答吵明白。
3. **最小掌控感（吃掉焦虑长出猫）**：从长篇焦虑帖里提炼出 **1 个今天花 3 分钟就能搞懂的核心概念或可执行微动作**。用户点下【我悟了 / 已拍板】，就相当于把这团焦虑“消化”成了自己的经验值，同时在圆桌小屋里**解锁一只对应主题的高颜值小动物/猫咪**。

## 五、 产品核心角色与四大功能模块设计

### 1. 「小动物圆桌」固定班底（Persona 设计）
利用知乎官方开放的 **刘看山 IP 素材** + **统一高颜值治愈系动物立绘（猫、狗、鸟）** 组成 4 人圆桌：
- 🦊 **圆桌主持 · 刘看山（人间清醒北极狐）**：负责控场、测量帖子的**「含焦量 / 幸存者偏差度 / 软广嫌疑度」**，一句话给出脱水省流结论。
- 🦉 **数据考据官 · 博士猫头鹰（理性派）**：专门调用 `search global`（全网搜索）与知乎高权威度（`AuthorityLevel >= 3`）回答，只摆客观统计数据、论文和官方信源，专治“身边即世界”。
- 🦔 **踩坑情报员 · 敏锐小刺猬 / 柴犬（经验派）**：专门调用 `search zhihu` 与 `question answers`，深扒知乎回答与精选评论区（`CommentInfoList`）里普通人最真实的血泪踩坑史与正反分歧点。
- 🐱 **治愈行动官 · 呼噜小猫（陪伴与养成派）**：负责给用户提供情绪安抚，把几千字的焦虑长文浓缩成一张**「3 分钟最小掌控感卡片」**；每当用户消化完一个焦虑或做好一个决定，就召唤新的主题猫咪入住图鉴。

### 2. 四大核心功能模块（用户完整体验流）

```
[入口1：知乎 OAuth 登录] ──► 生成《我的知乎冲浪体质 & 专属守护兽》报告（裂变拉新）
                                   │
[入口2：脱水知乎热榜 / 搜索任意问题 / 输入现实纠结]
                                   │
                                   ▼
                 ┌───────────────────────────────────┐
                 │      🐾 小动物圆桌庭审主舞台       │
                 ├───────────────────────────────────┤
                 │ 1. 含焦量与水分雷达（刘看山）      │
                 │ 2. 知乎过来人 vs 全网数据交锋（圆桌）│
                 │ 3. 3分钟最小掌控感提取（呼噜小猫）  │
                 └─────────────────┬─────────────────┘
                                   │ 点击【我悟了 / 拍板决定】
                                   ▼
         🎁 解锁对应知识主题的高颜值猫咪/小动物 + 存入清醒手账
```

#### 模块一：知乎 OAuth 裂变入口 ——《我的知乎冲浪精神状态 & 守护兽鉴定》
- 用户点击「用知乎账号领养守护兽」，完成 OAuth 授权。
- 后端拉取用户的 `me followees`（关注列表）、`me favorites recent`（近期收藏）、`me contents`（近期创作）。
- AI 结合这些真实数据，3 秒生成一张高颜值社交分享卡：
  - 诊断其冲浪体质（例如：*「深夜大模型追新焦虑症 · 硬核干货囤积松鼠」*）；
  - 当场孵化第一只专属于他知乎兴趣画像的**初始守护小猫/小动物**。
- *(注：未登录游客也可直接跳过此步，使用预设测试画像直接体验圆桌。)*

#### 模块二：左侧情报流 ——「真知乎实时热榜 · 防焦虑滤镜版」
- 实时拉取 `zhihu-cli hot` 真知乎热榜（服务端缓存 10–15 分钟以节省每日 100 次额度）。
- 每条热榜不仅显示原标题，还由后台轻量模型预标好**情绪天气预报标签**：
  - 例如：`⚠️ 焦虑预警 82%（幸存者偏差高发）`、`🍉 纯吃瓜 90%`、`💎 硬核认知增量`。
- 顶部支持直接输入任何纠结的问题（如*“2026 年还要不要转行做 AI 应用开发？”*）或直接粘贴任意知乎问题 URL。

#### 模块三：中央主舞台 ——「小动物圆桌庭审 & 脱水诊疗桌」
当用户点击一条焦虑热榜、或输入一个纠结问题时：
1. **第一幕：防焦虑脱水扫描（解决痛点 1）**
   - 展示**「情绪煽动水分 vs 真实干货密度」**可视化进度条；
   - 刘看山举牌指出该话题下最容易让人陷入 FOMO（怕落后）的话术陷阱（如“把前 1% 极客进度渲染成行业及格线”）。
2. **第二幕：小动物圆桌交锋（解决痛点 2）**
   - 画面中央的小动物依次弹出精炼气泡（支持流式动画与微表情切换）：
     - **支持/乐观方视角**（附带真实知乎高赞回答引用链接与作者，可点击溯源）；
     - **劝退/避坑方视角**（提炼知乎评论区真实反例与踩坑条件）；
     - **全网客观坐标**（对比知乎站外宏观数据，打破社区回音室）。
   - 如果用户正在做个人决策，圆桌会向用户追问 1 个关键取舍问题（如*“你目前更看重 1 年内的现金流，还是 3 年的技术复利？”*），根据用户的选择给出量身定制的拍板建议。
3. **第三幕：3 分钟最小掌控卡（把焦虑转化为行动）**
   - 呼噜小猫递出一张极简卡片：**「今日无需再刷同类焦虑帖！只需拿走这 1 块认知拼图」**（用 3 句话讲透该帖最核心的 1 个真概念，或给出 1 个 3 分钟内就能试一下的微动作）。

#### 模块四：右侧收集屋 ——「清醒猫咖图鉴 & 认知手账」
- 用户点击【吃掉这团焦虑 / 我做好决定了】后，触发治愈动画，根据刚才话题的领域（科技、职场、情感、商业、生活科普），在小屋里**诞生一只穿戴对应配饰的高颜值小动物/猫咪**（例如：读完 AI 架构帖解锁“头顶显卡的赛博布偶猫”，理清职业选择解锁“背着指南针的橘猫侦探”）。
- 点击屋里的每一只小动物，都能翻看它身上挂着的**「清醒手账」**（当时脱水提炼出的那条核心干货 + 原知乎问题链接），真正做到“看一篇、通一篇、攒一只猫”。

## 六、 知乎开放平台 API 与技术资源全量盘点（供 Claude 审阅）

我们解包了官方最新发布的 `zhihu-cli-skill.zip`（`v0.7.4`），发现除官网页面展示的 4 项基础能力外，文档还开放了另外 5 项隐藏能力。以下是完整的接口契约与配额表：

### 1. 接口清单、HTTP 端点与每日额度

| 能力分组 (`APIID`) | CLI 命令 | 原始 HTTP 端点 (`https://developer.zhihu.com`) | 每日免费额度 | 在本项目中的核心用途 |
| :--- | :--- | :--- | :---: | :--- |
| **知乎热榜** (`hot_list`) | `zhihu-cli hot --limit 30` | `GET /api/v1/content/hot_list` | **100 次/天** | 驱动「防焦虑滤镜版知乎热榜」（**必须做服务端缓存**，每 15 分钟更新一次全站共享，每天仅耗 ~96 次） |
| **知乎搜索** (`zhihu_search`) | `zhihu-cli search zhihu --query "..."` | `GET /api/v1/content/zhihu_search` | **5,000 次/天** | **主力接口**：拉取站内回答摘要、赞数、`AuthorityLevel`（1-4 权威度）、`CommentInfoList`（精选评论区），供小动物圆桌提取正反观点与辟谣 |

### 2. 鉴权与协议关键细节（避坑指南）
- **开放平台通用 Header**：
  - `Authorization: Bearer <ZHIHU_ACCESS_SECRET>`
  - `X-Request-Timestamp: <Unix 秒级时间戳>`
- **黑客松 OAuth 协议实测注意点（来自官方 `oauth.md` & `hackathon-user-profile-api.md`）**：
  1. 授权跳转地址：`GET https://openapi.zhihu.com/authorize?redirect_uri={redirect_uri}&app_id={app_id}&response_type=code`
  2. **回调参数名坑点**：知乎线上回调实际带回的 Query 参数名是 `authorization_code`（而非标准 `code`），后端接收时应兼容 `req.query.authorization_code || req.query.code`，并在换取 Token（`POST https://openapi.zhihu.com/access_token`）时将其作为表单字段 `code` 提交。
  3. **大整数精度坑点**：`GET https://openapi.zhihu.com/user` 返回的 `uid` 是 `int64`（如 `969570047710216200`），超过 JS `Number.MAX_SAFE_INTEGER`，必须在 JSON 解析阶段用正则或 `json-bigint` 转字符串处理。
