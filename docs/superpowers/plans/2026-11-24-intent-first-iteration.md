# 从总设计稿到正式小屋｜技术路径与第 1 轮迭代

**设计依据：**[产品总设计稿 v1.0](../specs/2026-11-24-intent-first-cabin-design.md)，尤其是 §2 的 A–F。**交付对象：**真实的 Next.js 伴读页，不是另做一份演示。检验的不是能说多少句，而是「读者改口后的第一句有没有接对」。

## 技术取舍

| 路径 | 为什么用 / 不用 |
| --- | --- |
| 继续预排四人台词 | 适合讲解已读材料，可保留为可选的文章导读。不适合插话：队列里早已没有读者刚说的话。 |
| 每次把聊天历史发给模型 | 有机会理解更多说法，但改变了私聊不出本机的约定；还得解决超时、失联与迟到的旧回复。这一轮不用。 |
| 本机逐轮判断，资料单独取证 | **这轮采用。** 最新一句优先，分别记录「想不想做」「卡在哪里」「想要哪种回应」。只在当前桌沿用未说完的线索；不懂时宁可少说，不把分类当人物画像。选中意图后才决定谁开口、是否需要引文。 |

## 本轮施工顺序与验收

1. **先用读者原话把错误重现。** `scripts/intent.test.mjs` 从正式对话入口 `say` 测同桌连续改口、D/E 单独开局、点名、否定、换题、不知道、已知难处、纠正及来源不足。不测某六句必须逐字输出。
2. **拆开判断与发言。** `src/lib/turn-intent.ts` 只判当前需求和同桌尚有关联的阻碍；`src/lib/turn-reply.ts` 组织一条适合该伙伴的回应。查原文只看当前篇/选句；可以说不知道。不读取手账、其他桌或主动便签来猜意图。
3. **把话头交给读者。** `src/lib/companion.ts` 和 `src/lib/storage.ts` 允许无文章的窗边谈话；旧存档仍能打开。打断导读后旧台词失效，仍可主动打开原文卡。`src/app/page.tsx`、`CabinModal.tsx` 接入提前输入、取消迟到的回执、收屋与重开。不给读者看意图标签，不加速换立绘。
4. **屋外只邀请，进屋才接上次的话。** 空闲和限频规则仍在 `companion.ts`。一张待领便签不是一条已发聊天；收屋后不把私事写进屋外提示或增加聊天条数。主动点便签才在原桌揭开。
5. **端到端检查。** `npm run test:companion` → `npm run typecheck` → `npm run build` → `npm run test:companion:api`；再在生产界面用 Playwright 试空手开桌、选句、连着改口、折叠/重开、草稿与延迟回执。用编辑室试读/本地测试替身，不拿真实用户的聊天做样本。保留已有三视图、十二张立绘、开场动画及首页展示。

**交付对照：**[正式界面、已跑检查与五人试用提纲](../../intent-first/README.md)。设计标签保留在迭代前，方便对照目标与实际。

## 后续次序（不是本轮承诺）

- **先让五位读者试这一轮。** 用未见过的自然表述，记首句是否接对、是否再追问、是否得重新解释。只记匿名观察。先分清是没认出需求，还是认对了但措辞不合适，再决定是否引入可选模型；不以规则测试通过率冒充用户满意度。
- **然后拆记忆。** 把本页阅读线索与读者的永久书架分开。共享关键谈话记忆须带读者自己的依据、允许纠正/忘记/禁止主动提起；拿「只读没聊」和「一个月前亲口聊过」做对照，再放开七天限制。做「上次想到这儿」的自愿念头书签，不覆盖原句书签。
- **最后做旁听。** 取到真实的知乎榜首才出题，不喜欢就换；有范围时站内检索。需要自动接话时再加可取消的逐句队列，输入/收屋立即让位。没取到内容不造新闻，不把下一题当成自动播完整轮的许可。
